# Contributing to Budget Padmanaban

Thank you for your interest in contributing to Budget Padmanaban! 🎉

## Project Status

This is a portfolio/learning project primarily developed to demonstrate:
- Modern Flutter development practices
- Supabase integration
- AI/ML features in mobile apps
- Clean architecture and state management

## How to Contribute

While this is a personal project, contributions are welcome! Here's how you can help:

### 1. Reporting Bugs

If you find a bug, please create an issue with:
- Clear title and description
- Steps to reproduce
- Expected vs actual behavior
- Screenshots (if applicable)
- Device/OS information

### 2. Suggesting Features

Feature requests are welcome! Please:
- Check if the feature is already planned (see README roadmap)
- Explain the use case
- Describe expected behavior
- Consider implementation complexity

### 3. Code Contributions

#### Before You Start
1. Fork the repository
2. Create a new branch (`git checkout -b feature/amazing-feature`)
3. Check existing issues to avoid duplicates

#### Development Setup
```bash
# Clone your fork
git clone https://github.com/YOUR_USERNAME/budget-padmanaban-ai-expense-tracker.git

# Install dependencies
flutter pub get

# Follow SETUP_GUIDE.md for Supabase configuration
```

#### Code Standards
- Follow Dart style guide
- Run `flutter analyze` (must pass with 0 issues)
- Run `flutter test` (all tests must pass)
- Add comments for complex logic
- Update documentation if needed

#### Commit Messages
Use clear, descriptive commit messages:
```
feat: Add budget alerts notification feature
fix: Resolve expense list pagination issue
docs: Update setup guide with iOS configuration
style: Format code according to dart style guide
refactor: Optimize expense query performance
```

#### Pull Request Process
1. Update README/docs if needed
2. Ensure code passes all checks
3. Write clear PR description:
   - What changes were made
   - Why they were made
   - How to test them
4. Link related issues
5. Wait for review

### 4. Documentation

Help improve documentation:
- Fix typos or unclear instructions
- Add missing setup steps
- Translate to other languages
- Add code examples

### 5. Testing

- Write unit tests for new features
- Test on different devices
- Report platform-specific issues

## Development Workflow

### Branch Naming
- `feature/` - New features
- `fix/` - Bug fixes
- `docs/` - Documentation updates
- `refactor/` - Code refactoring
- `test/` - Test additions/updates

### Code Review
- All PRs require review
- Address review comments
- Keep discussions professional and constructive

## Getting Help

- **Questions**: Open a GitHub Discussion
- **Bugs**: Create an issue with bug template
- **Features**: Create an issue with feature template
- **Chat**: Open an issue for general discussion

## Project Structure

Refer to README.md for detailed project structure. Key areas:
- `lib/features/` - Feature modules
- `lib/core/` - Shared utilities and widgets
- `lib/services/` - Backend services
- `lib/models/` - Data models

## What We're Looking For

Priority areas for contribution:
1. ✅ Test coverage improvements
2. ✅ Performance optimizations
3. ✅ UI/UX enhancements
4. ✅ Accessibility improvements
5. ✅ Documentation improvements
6. ✅ Bug fixes

## What to Avoid

- Breaking changes without discussion
- Large refactors without prior approval
- Style-only changes (unless fixing lint issues)
- Dependencies without clear benefit

## Code of Conduct

### Our Standards
- Be respectful and inclusive
- Accept constructive criticism gracefully
- Focus on what's best for the project
- Show empathy towards others

### Unacceptable Behavior
- Harassment or discriminatory language
- Trolling or inflammatory comments
- Personal attacks
- Publishing private information

## Recognition
